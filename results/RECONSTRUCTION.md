# Reconstructing the headline numbers by hand

Generated by `scripts/manifest.py` from `params/parameters.yaml`. Every figure below is
computed by the same code that produces the manuscript, so this worksheet cannot drift from
the paper. It exists so that a reader can reproduce the three headline results with a
calculator, without running the model and without having to ask what an input means.

Each line gives the arithmetic, the inputs by parameter name, and where the input came from.
Full sources are in `results/parameter_manifest.csv`; the attempt-cost inputs with their
usage allocations are in `results/fee_schedule_manifest.csv`.

## 1. Cost per synthesis attempt

Each line is a published rate times an allocation to one attempt. The allocations are
assumptions, not measurements, and are named in the fee manifest.

Labour and tuition are divided by attempts per year = `synth.weeks_per_year` x `synth.labour_attempts_per_week` = 52 x 15 = **780**.

| Component | Arithmetic | USD |
|:--|:--|--:|
| XRD | one sample at `synth.xrd_cost_per_sample` = $80.00 | $80.00 |
| Furnace | `furnace_fixed_fee` $6.00 + `furnace_hourly` $3.45 x 9.246 h | $37.90 |
| Labour | `labour_annual_salary` $29,364.00 x (1 + 0.075) / 780 | $40.47 |
| Tuition | `labour_tuition_remission` $16,000.00 / 780 | $20.51 |
| Crucible | `crucible_cost` $69.75 / `attempts_per_crucible` 20 | $3.49 |
| Precursors | `precursor_mass_g` 1.5 g x `precursor_usd_per_g` $1.76 | $2.64 |
| Other consumables | `other_consumables_per_attempt` | $5.58 |
| **Direct subtotal** | sum of the rows above | **$190.59** |
| Indirect (F&A) | base $190.59 x `synth.indirect_rate` 42% | $80.05 |
| **Total per attempt** | | **$270.64** |

On a direct-cost-only basis (no F&A) the attempt is $190.59. The F&A base is
total direct costs *including* service-centre fees and tuition, because the 42% figure is
defined by its source over total direct costs; an MTDC-like base is carried as a scenario.

## 2. Cost per experimentally validated material

$$C \;=\; \frac{c_0 + r\,a}{S}$$

| Symbol | Meaning | Value | Where it comes from |
|:--|:--|--:|:--|
| $a$ | cost per attempt | $270.64 | section 1 above |
| $r$ | recipes per target | 6.193 | `synth.recipes_per_target`: 353 experiments / 57 targets in the reference campaign |
| $S$ | unconditional synthesis success | 0.4375 | `synth.success_unconditional`: 36 of 57 targets, campaign-observed, NOT conditioned on a correct stability label |
| $c_0$ (A) | upstream compute per candidate reaching synthesis | $26.44 | affine in DFT cost; section 3 below |

At base: (26.44 + 6.193 x 270.64) / 0.4375 = (26.44 + 1,676.05) / 0.4375 = **$3,891.40** for pipeline A.

$c_0$ for B and C is $16.00 and $64.35, giving $3,867.55 and $3,978.05. The
three differ only through $c_0$, because $r$, $a$ and $S$ are assumed shared.

**$S$ is unconditional, which matters.** It is the share of *attempted targets* that were
made, so it already includes targets whose stability label was wrong. Multiplying it by a
label-accuracy factor would charge those failures twice. A consequence is that the
stable-to-unstable transition rate $w$ cancels from this equation entirely: level-1 cost is
per robust prediction, so $c_0 = (1-w)c$ and the factors cancel.

## 3. The threshold crossings

Upstream compute per candidate reaching synthesis is affine in DFT cost $d$ in core-hours:

$$c_{0i}(d) \;=\; \alpha_i d + \beta_i$$

| Pipeline | $\alpha$ (USD/core-h) | $\beta$ (USD) |
|:--|--:|--:|
| A | 0.4847826087 | 0.0006416897 |
| B | 0.2934210526 | 0.0015626629 |
| C | 1.1736842105 | 0.3381360265 |

$\alpha$ carries the compute price (`compute.price_per_core_hour` = $0.04/core-h) and the number of candidates verified per
candidate reaching synthesis, which is where pool prevalence and filter purity enter.
$\alpha_C/\alpha_B$ = 4.000000, exactly the purity ratio 0.152/0.038.

Setting $(C_C - C_B)/C_B = \tau$ and solving for $d$:

$$d^{*} \;=\; \frac{\tau b + (1+\tau)\beta_B - \beta_C}{\alpha_C - (1+\tau)\alpha_B}\;,\qquad b = ra$$

With $b$ = 6.193 x 270.64 = $1,676.05 and $\tau$ = 0.10:

- numerator: 0.10 x 1676.0479 + 1.10 x 0.0015627 - 0.3381360 = 167.268373
- denominator: 1.1736842105 - 1.10 x 0.2934210526 = 0.850921
- $d^{*}$ = 167.268373 / 0.850921 = **196.5733 core-hours**, which the model's bisection also returns as 196.5733.

A positive denominator is necessary but not sufficient: $d^{*}$ must also be nonnegative to
lie in the domain. The filter crossing, with $\alpha_A$ in place of $\alpha_C$, is 1,034.5 core-hours.

## 4. The synthesis decision boundaries

Relaxing the shared-synthesis assumption, parity between two pipelines needs

$$\frac{S_i}{S_j} \;=\; \frac{c_{0i} + ra}{c_{0j} + ra}\;,\qquad \Delta r \;=\; \frac{c_{0i} - c_{0j}}{a}$$

- generative vs filtered: (64.35 + 1,676.05) / (16.00 + 1,676.05) = **1.0286**, so 2.9% better success.
- filter vs none: (26.44 - 16.00) / 270.64 = **0.0385** extra recipes, 0.62% of 6.193.

Both are break-even solves. No source measures a pipeline-specific synthesis difference.


The Monte Carlo is seeded from `monte_carlo.seed` in the parameter file, so the draw-level
outputs are reproducible byte for byte on the same Python version.
