# DFT (Quantum ESPRESSO) timing benchmark: protocol and results

Generated by `benchmarks/dft/report_dft.py`. Every number in the text is computed at write time from `timings.csv`,
`benchmarks/mlip/timings.csv`, `qe_env.json`, `pseudo_gbrv/library.json`, `run_log.txt`, `clock_events.txt`, the
benchmark code's constants and the machine. Each calculation's pw.x input and output text is in `runs/`. Companion to
`benchmarks/mlip/PROTOCOL.md`; same 7 starting structures (`benchmarks/mlip/structures/`, as-generated
and unrelaxed). These are PBE calculations run to measure cost; they do not validate any candidate. **Pseudopotentials
are GBRV ultrasoft, not the planned SSSP, because of a Materials Cloud outage (§4).**

**The primary DFT cost figures are at 4 MPI ranks** (`config=primary_4rank`, 3 repeats per
structure), reported as the **median** of the repeats; repeats form a tight distribution with occasional slow outliers
(worst max/min within a structure: 2.2×), reported separately as a platform observation
(§7.6). 12-rank runs cost 2.6–7.3× (well constrained only from same-session pairs: 7.32× at 10 atoms and 3.86× at 20 atoms; the rest single cross-session runs, §7.2) the core-hours of 4 ranks for the same SCF on
this machine. The penalty is largest for the smallest cell and shows no clear dependence on size across the rest
(§7.2), so the original 12-rank runs are kept only as a documented platform artefact
(`config=original_12rank`), and the 12-rank vc-relax costs are reported unscaled as upper bounds (§7.4).

**Design.** Relaxation cost at size N = (cost per SCF iteration at N) × (SCF iterations per ionic step) × (ionic steps).
(a) Single-point SCF on all 7 structures (10–56 atoms), 3 repeats
each, gives cost per SCF against size. (b) Full vc-relax on the 4 smallest (10–20 atoms)
gives ionic steps and SCF iterations per ionic step, both roughly size-independent. The three factors are recorded
separately so the cost at larger N can be extrapolated rather than guessed. (c) The 20-atom
SCF at 1, 4, 12 MPI ranks measures parallel efficiency.

## 3. Software

- **Quantum ESPRESSO:** 6.7MaX (Ubuntu 26.04 package quantum-espresso 6.7-4build1, arm64). Newer QE releases are faster in places, so these timings
  describe QE 6.7MaX.
- **Install:** apt-get download + dpkg -x into ~/.local/qe/root (no sudo available; no compiling). Ubuntu 26.04 arm64 packages.
- **MPI:** OpenMPI 5.0.10-1 (Ubuntu openmpi-bin), `mpirun -np <ranks>` with default binding. **k-point pools**: `-nk` = the
  largest of 1, 2, 4 dividing the rank count (1 ranks → 1 pools × 1; 4 ranks → 4 pools × 1; 12 ranks → 4 pools × 3), the same rule for every run.
  An untimed setup check showed plane-wave-only parallelisation (`-nk 1`) to be much slower per SCF iteration on these
  small cells (values in the run log, §10; not saved as data). Pools change only how work is split, not the result.
- **BLAS/LAPACK:** OpenBLAS 0.3.32 serial (libopenblas0-serial); FFTW3 (libfftw3-double3); ScaLAPACK (libscalapack-openmpi2.2).
- `OMP_NUM_THREADS`, `OPENBLAS_NUM_THREADS` and `MKL_NUM_THREADS` are set to one thread for every run (pure MPI, one
  rank per core).

## 5. Fixed calculation settings (identical for every structure)

- PBE (from the pseudopotentials), plane waves, GBRV ultrasoft pseudopotentials (§4).
- Cutoffs: **ecutwfc = 40 Ry, ecutrho = 200 Ry** for all elements (Ba, F, In, Li, Mn, N, Na, O, P, S, Si, Ti, Zn)
  and all runs.
- k-points: Monkhorst-Pack Γ-centred grid (no offset), n_i = max(1, ceil(|b_i| / 0.3 Å⁻¹)) with |b_i|
  including 2π (VASP KSPACING convention), from the starting cell.
- Smearing: Marzari-Vanderbilt cold smearing, degauss = 0.01 Ry.
- Spin: collinear spin-polarised, ferromagnetic start (starting_magnetization 0.5 on Mn),
  for structures containing Mn; non-spin-polarised otherwise. No Hubbard U.
- SCF: conv_thr = 1e-08 Ry, mixing_beta = 0.4, electron_maxstep = 200.
- vc-relax: BFGS for ions and cell, cell_dofree = 'all', forc_conv_thr = 1.9447e-03 Ry/Bohr (= 0.050
  eV/Å, the MLIP fmax, so ionic step counts are comparable), etot_conv_thr = 1e-04 Ry, press_conv_thr =
  0.5 kbar, nstep = 200.
- disk_io = 'low'; each run's scratch directory is deleted before and after the run.

Caps: the phase budget (ranks × wall / 3600 summed over the phase's runs; before each run its kill timer is set to
min(90 min, remaining budget / ranks), so a budget can be overshot only by the seconds a kill takes, and a phase
stops when less than 60 s would remain) and **90 minutes wall-clock per calculation**
(killed with SIGTERM, then SIGKILL; `exceeded_cap=true`, `cap_reason` says which cap). Strictly serial: one calculation
at a time. `wall_clock_s` = monotonic wall time (`time.perf_counter`) around `mpirun`, including MPI start-up and pw.x
setup; QE's own timer is kept in `qe_reported_wall_s`. `n_scf_steps` = total SCF iterations (summed over ionic steps for
vc-relax); `n_ionic_steps` = number of SCF cycles that reached a total energy (`!` lines).

**Controlled size comparison.** `mp-19017-sub010` (28 atoms) vs `LiMnPO4_2x1x1` (56 atoms, its
2×1×1 supercell): same chemistry, same pseudopotentials, exactly 2× the
atoms. Median core-hours per SCF at 4 ranks: 0.480 vs 3.842, a factor of
8.00, i.e. a scaling exponent of **3.00** in total SCF cost.

k-point density was **not held exactly constant**: the
mesh went 3×4×5 → 2×4×5 (3 → 2 along the doubled `a` axis;
halving would need a non-integer count, and the k-spacing rule rounds up). QE's irreducible
k-point count went 18 → 22 (×1.22) and SCF iterations 13 →
17 (×1.31); bands 113 → 226, dense-grid G-vectors
94911 → 189799. So the exponent of 3.00 **includes** more k-points and more SCF
iterations in the larger cell; per SCF iteration it is 2.61, and per SCF iteration per irreducible
k-point 2.32. The per-k-point scaling is therefore shallower than the total.
This is one pair at one size step (28 → 56 atoms); it is not a fitted law and should not be
extrapolated far beyond this range.

12-rank run, `top` showed nearly all CPU time as user time (values in the run log, not saved as data), so the
MLIP kernel page-fault artefact does not appear to be what limits QE here; the cause of the cliff is not diagnosed.

## 8. Deviations from the request

- **Pseudopotentials:** GBRV ultrasoft instead of SSSP efficiency (Materials Cloud outage, §4). Cutoffs follow GBRV's
  design (40/200 Ry) instead of SSSP's per-element recommendations.
- **QE install:** `sudo apt install` was impossible unattended (sudo needs a password); the same Ubuntu packages were
  unpacked into the home directory (§3). QE is version 6.7MaX.
- **k-point pools:** added after an untimed setup check (§3, §10); parallelisation only.
- **Ranks:** the request specified `mpirun -np 12` for the main runs. Those runs cost 2.6–7.3× (well constrained only from same-session pairs: 7.32× at 10 atoms and 3.86× at 20 atoms; the rest single cross-session runs, §7.2) the
  core-hours of 4 ranks, so the SCFs were rerun at 4 ranks (user decision) and the
  vc-relaxes are reported unscaled as 12-rank upper bounds (§7.4): the penalty at their sizes lies
  between 2.6× and 7.3× with no clear size dependence, so no factor could rescale them reliably.
- **Rank check incomplete:** the interleaved check ended early (thermal shutdown) and was not resumed (user decision);
  Li2MnSiO4 (32 atoms) was not completed (§7.2).
- **Repeats:** the original phase's budget ran out before its SCF repeats; the 4-rank phase runs
  3 repeats per SCF.

## 9. Hardware generalisability

Same machine as the MLIP benchmark: **Qualcomm Snapdragon X (Oryon, 12 cores, ARM64), Surface Pro 11, Linux under
WSL2** (Hyper-V virtual CPUs), 15.4 GiB RAM, fanless. The MLIP benchmark found that many busy cores on this
platform run far slower than their count suggests (`benchmarks/mlip/PROTOCOL.md` §8–9). DFT shows its own cliff past
4 MPI ranks (§7.2), which is why the primary figures are at 4 ranks; the
1-rank point is the cleanest per-core figure. On a different machine the best rank count will differ. Ubuntu's generic QE
6.7MaX build with OpenBLAS is not a tuned HPC build (no vendor BLAS/FFT, no GPU), and ARM laptop cores differ from
server vCPUs, so absolute times are indicative of this hardware class only. Ratios of factors (SCF iterations per ionic
step, ionic steps) transfer better than wall times.
